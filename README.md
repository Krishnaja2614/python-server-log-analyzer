# Python Server Log Analyzer

A beginner-friendly Python tool for analyzing server logs, identifying recurring errors, and generating reports with troubleshooting recommendations.

## Overview

Server logs help IT support teams investigate errors and understand system behaviour. Manually reviewing large log files can be time-consuming.

This project automates basic log analysis by counting log levels, detecting malformed entries, identifying recurring errors, and generating a CSV report with suggested next troubleshooting steps.

## Features

* **Log parsing:** Reads timestamped server log entries from a text file.
* **Log classification:** Counts `INFO`, `WARNING`, and `ERROR` entries.
* **Error frequency analysis:** Identifies recurring error messages and ranks them by frequency.
* **Input validation:** Skips malformed or unsupported log entries.
* **Troubleshooting guidance:** Provides rule-based suggestions for recognised errors.
* **CSV reporting:** Exports log-level counts, error occurrences, and suggested next checks.
* **File error handling:** Handles missing or unreadable input files and report-writing errors.
* **Automated tests:** Includes basic unit tests for error counting, log-level counting, and empty input.

## Getting Started

### Prerequisites

* Python 3 installed on your computer.
* A terminal or command prompt.
* Git installed if you want to upload the project to GitHub.

### Run the project

1. Clone the repository or download the project files.
2. Open the project folder in VS Code.
3. Open a terminal in the project directory.
4. Run the analyzer:

```bash
python log_analyzer.py
```

On Windows, you can also use:

```bash
py log_analyzer.py
```

The program reads `sample.log`, displays the analysis in the terminal, and creates `report.csv`.

### Run the tests

Execute:

```bash
python -m unittest -v
```

The included tests check error-frequency counting, log-level counting, and empty input.

## Troubleshooting Scenarios

| Scenario                 | Expected behaviour                                              |
| ------------------------ | --------------------------------------------------------------- |
| Repeated database errors | Counts occurrences and suggests connectivity checks             |
| Request timeouts         | Suggests investigating service availability and network latency |
| Malformed log entries    | Skips invalid entries and tracks their count                    |
| Missing input file       | Displays a clear error message and stops analysis               |
| Report-writing failure   | Displays a file-writing error message                           |

The recommendations are rule-based starting points, not confirmed root-cause diagnoses. Further investigation is required before taking corrective action.

## Limitations

* Supports a defined log format and the `INFO`, `WARNING`, and `ERROR` levels.
* Uses predefined troubleshooting rules rather than automated root-cause analysis.
* Analyses local sample files; it does not connect to live servers or cloud logging services.
* Included unit tests validate counting logic and empty input, not the entire end-to-end workflow.
